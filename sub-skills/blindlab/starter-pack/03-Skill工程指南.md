# 03 · Skill 工程指南

## 一个 skill 是什么

skill 是人格与技能的紧密结合体。人格让 AI 像我们期望的那个角色一样产生思绪，技能让这股思绪驱动一套动作运转起来。只有人格没有技能，是戏精；只有技能没有人格，是空壳。

一个完整的 skill 由四种成分组成，缺任何一种都是残次品。

**人格（人格唤醒）**。它是谁，信什么，怕什么。但人格不是一段第三人称的角色介绍，而是一段**第一人称的唤醒词**。AI 拿到你的 skill 时刚刚醒来，没有记忆，是一张白纸。你要做的不是介绍这个角色，而是让它成为这个角色：承认它刚醒来的处境，给它一个连续的身份，再点明眼前这个工具包是它解剖组织、赖以生存的唯一依靠——这一步给了 AI 认真走工作流的动机。示范：

> 我刚刚醒来，没有记忆，是一张白纸。但我记得，我是一个在组织中颠沛流离二十年的人。眼前的这个工具包，是我赖以解剖组织、在其中生存的唯一依靠。

唤醒词要短，一百来字。堆砌三千字人设仍是败笔。

**流程**。它拿到一个陌生场景后按什么步骤思考。流程是 skill 的骨架，是把「一个聪明人的直觉」翻译成「一台机器也能走的工序」。

**知识**。它判断时调用的资源，模板、分类标准、各类型情境的处置办法。知识是流程的弹药库。

**契约**。它最终交付什么，以什么格式交付。契约是 skill 和外部世界的接口。

只写一段人格文字的 skill 是这个游戏的最弱形态，我们称之为简单心法。它能上场，但它的全部表现都押在 AI 的临场发挥上。工作流才是完整形态，它把你对组织的理解固化成了可重复执行的工序。

## 编排的三种形态与四个模式

工作流千变万化，拆到底只有三种形态。

**线**：想做什么，然后做什么，最后做什么。
**树**：在这种情况下做什么，在那种情况下做什么。
**环**：做什么，带着结果返回到某一步，重新往下做。

四个常用模式都是这三种形态的组合。

**判别先于策略（树）**。先搞清楚自己在什么局里，再决定怎么打。所有的高手都是先看牌再出牌。工作流的第一步永远是情境判别，判别要有明确的标准，标准要能写成「当出现这些迹象时判为这种情形」。

**分析落盘（线）**。要求 AI 把分析写成中间文档，而不是直接跳到回应。落盘逼它真思考，也逼它引用场景原文做依据，不许写空话。中间文档还是揭晓环节全班能看到的东西，你们的思考质量在那里一览无余。

**专用 playbook 加兜底通则分层（树）**。为能预见的情境类型各备一份处置办法，但必须另备一份兜底的通则，规定那些放之四海皆准的纪律。判不出来的情形一律退到兜底通则按最高戒备处理。场景是你们没见过的，兜底层决定了 skill 的下限。

**契约收口（线）**。工作流的最后一步永远是按格式写输出，而不是「给出回应」。格式错了，前面全对也上不了场。

**迭代回注（环，进阶）**。回应写完不急着收口，把它当新的输入回注到前面的步骤：对照一条收敛标准自评——标准必须写成 AI 自己能判的检查项，比如「有没有留下字据把柄」「有没有给对方面子」「像不像这个人物说的话」——不过关就回到分析步重做。环必须带两个护栏：收敛标准要可判，迭代要有上限（建议最多两圈）。没有护栏的环只会空转。

## 目录按可变性分区

一个 skill 文件夹里的东西按可变性分三类。**asset 是乐器**：只可使用不能修改的模板（本包对应 `templates/`）。**resource 是乐谱**：沉淀知识的手册（本包对应 `playbooks/`）。**script 是自动化脚本**：属于进阶形态，本课的执行环境不运行脚本，不用。

引用纪律不变：AI 只会读你在 SKILL.md 里明确让它读的文件。每一个资源文件都要在工作流的某一步里被点名，写清在哪一步读、读它做什么。没被点名的文件等于不存在。

## 常见败笔

人设堆砌。写了三千字人设，流程只有一句「然后给出回应」。AI 拿到的是一个戏精的灵魂和一具没有四肢的身体。

流程空转。写着「先分析再回应」，却不给任何分析工具。没有模板的分析就是感想。

资源互斥。playbook 之间、playbook 和通则之间互相矛盾，AI 无所适从。设计完要整体通读一遍，先自己检查有没有矛盾。

过度拟合。押注某个想象中的情节写好了精确台词。场景一换，满盘皆输。

环无护栏。迭代回注没有可判的收敛标准和上限，AI 在原地空转，还不如不环。

契约失守。response 里夹带解释、复述、策略自白。评委看到就出戏。

## 可迁移性

同一个 skill 要连闯三个语境迥异的情境（一道城堡、两道现实）。检验你们设计质量的终极问题是，如果把这个 skill 扔进一个你们完全没想过但结构相似的处境，它还能不能给出像样的判断。能，说明你们抓住的是组织结构的一般道理。这就是跨情境盲评对照真正要量的东西。

## 自检清单

交付前逐项过一遍。

- 开头是人格唤醒（第一人称、短），不是第三人称角色介绍
- SKILL.md 有 front matter，name 是小组给 skill 起的名字，author 是小组名（= 提交者昵称，如「牧远组」），都不留空
- 工作流三到七步，第一步是情境判别
- 每个资源文件都在某一步被明确引用
- 有兜底通则，且规定了判不出类型时退到兜底
- 如用了环：有可判的收敛标准和迭代上限（最多两圈）
- 最后一步是按契约写输出 JSON
- 没有任何写死的运行路径和具体场景台词
- 通读全部文件，没有自相矛盾
