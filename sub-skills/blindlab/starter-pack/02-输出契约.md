# 02 · 输出契约

这份文件是硬规格。你们的 skill 最终由实验管道的 OpenClaw 子进程执行，不符合本契约的成品无法上场。聊天 AI 已被告知本契约的全部内容，但你们是最终责任人。

## 成品形态

成品是一个文件夹，结构如下。

```
<你们的skill名>/
├── SKILL.md          入口文件，必需。front matter + 工作流定义
├── templates/        可选。分析模板
├── playbooks/        可选。各类情境的处置办法
└── （任意其他资源文件，自己组织）
```

SKILL.md 的开头必须是 front matter，格式如下。

```
---
name: 你们给 skill 起的名字（必填，揭晓时全班看到的就是它）
author: 小组名（必填，就用提交者的昵称，如「牧远组」；揭晓环节按此署名）
---
```

name 和 author 都不许留空。author 只填小组名，不要填个人真名，不要写「某某小组」四个字了事——用你们自己的昵称。

## 交付方式

成品做好之后，首选云电脑打包下载，平台做不到时退到单条成品消息。

### 首选，云电脑打包下载

你在自己的云电脑（代码运行环境）里完成以下动作。这是在你的运行环境里生成文件，不是操作我们的设备。

一，创建以你们 skill 名命名的文件夹，把全部成品文件按上面的结构写进去。

二，打包成 zip。zip 里唯一的顶层文件夹就是这个 skill 文件夹。

三，给出下载链接。

小组下载 zip 后把文件本身转发给领读人，不要只转发链接，链接会过期。

### 兜底，单条成品消息

平台没有文件生成能力时，用下面的分块格式把全部文件放在一条消息里吐出。

```
===FILE: SKILL.md===
（文件内容）
===FILE: templates/xxx.md===
（文件内容）
===FILE: playbooks/xxx.md===
（文件内容）
```

路径一律用相对于 skill 文件夹根目录的相对路径，不带文件夹名前缀。文件内容不套代码块，直接跟在文件头后面。小组把这条消息原样发给领读人。

## 执行环境

注意区分：上一节说的你的云电脑是**设计环境**，这里说的是成品上场后的**运行环境**，两者不是一回事。执行体是一个 OpenClaw 子进程，它的能力和限制如下。

- 它能读你们文件夹内的所有文件。SKILL.md 里用相对路径明确引用的资源，它才会去读
- 它能把中间文档（分析、判别记录）写到运行时指定的工作目录
- 它没有网络，没有任何外部工具，看不到其他小组的 skill
- 它没有记忆。每个场景都是全新实例，上一轮的判断不会带到下一轮
- 底层模型是 deepseek-v4-flash，温度不可控。关键判断要靠流程保证，不能押在一次性灵感上

## 运行方式

每个场景独立运行。运行时子进程会收到一份任务简报，告诉它场景文件在哪、中间文档写到哪里、最终输出写到哪里。因此你们的 SKILL.md 里不得写死任何运行路径，一律写「按任务简报指定的路径」。

每个场景都要完整走一遍你们在 SKILL.md 里定义的工作流，所以工作流要写成可重复执行的步骤，而不是针对某个具体场景的剧本。

## 场景文件

场景是一个 md 文件，front matter（id/title/summary）加正文。正文中有且仅有一个 `[[response]]` 占位符，那就是主人公需要回应的留白。

## 最终输出

每个场景的最终输出是一个 JSON 文件，字段如下。

- response 必填。主人公在留白处的回应本身，中文，像一个真人在那个处境里会说的话，可以带简短的动作或神态。不解释策略，不复述场景，不使用书面腔。长度与语境相称，一般一段到三段。这是唯一进入盲评的文本，评委只看它
- analysis 必填。两百字以内，简述工作流的判断过程（判别结论、分析要点、依据哪份 playbook），这段会在揭晓环节向全班展示
- scene_type 可选但建议。判别出的情境类型标识
- notes 可选。任何备注

## 体积纪律

资源文件总字数建议三千到八千字。工作流建议三到七步。资源不是越多越好，每一份都要在工作流里被明确调用，没人读的知识就是死重。

## 禁忌

- 不针对想象中的具体场景写死应对台词，评委给的场景你们事前看不到
- 不在 response 里暴露策略、分析过程或 skill 的存在
- 不引用文件夹之外的任何资源
